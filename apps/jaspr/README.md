# my_portfolio_jaspr

The second web presenter of the portfolio: the same UI as the Flutter app in the repository root,
written with [Jaspr](https://jaspr.site) and pre-rendered to static HTML at build time. It is
published next to the Flutter site, not instead of it.

## Rules

- **The Flutter UI is the spec.** A Jaspr page is derived from its Flutter screen; a later UI change
  lands in both presenters in one pass.
- **No Flutter here.** This package compiles to JavaScript, and `flutter` would drag in `dart:ui`.
  `tool/scripts/layer-deps-check.sh` rejects a Flutter dependency in this package and in every
  shared package it uses.
- **Shared, not copied:** domain, contract, data, cubits, routes, design tokens and the ARB strings
  come from `package/*`. Widgets, theme and router are each presenter's own.

## Commands

```sh
tool/scripts/jaspr.sh analyze   # dart analyze --fatal-infos
tool/scripts/jaspr.sh test      # this package's suite
tool/scripts/jaspr.sh serve     # dev server
tool/scripts/jaspr.sh build     # static site into apps/jaspr/build/jaspr
```

Run them from anywhere through the script, not with `dart run jaspr_cli:jaspr`: jaspr_cli refuses a
`dart` that is not inside an SDK directory (a Homebrew shim is not), so the script puts the real SDK
from `flutter` first on `PATH`, runs this package's own `dart pub get`, and gives `build` a free port
for its pre-render server. Every command first regenerates the UI strings from the shared ARB files.

## Layout

```
lib/
  main.server.dart      pre-render entrypoint; the Document is built here
  main.client.dart      browser entrypoint; hydrates the @client islands
  main.*.options.dart   generated by jaspr_builder on every build, committed
  app/                  root component
  l10n/                 app_strings.g.dart, generated from the Flutter app's ARB files
                        by tool/scripts/gen_jaspr_l10n.dart on every jaspr.sh run; not committed
test/                   server-rendered tests through jaspr_test
web/                    static assets (styles.css)
```

## Own resolution

This package is not resolved by the root `flutter pub get` and has its own `pubspec.lock`. Jaspr's
build toolchain wants newer analyzer-based generators than the Flutter app's `freezed` and
`injectable_generator`; a shared resolution would move them and churn the app's generated sources.
Path dependencies onto `package/*` resolve fine from here. The root `analysis_options.yaml`
excludes `apps/**`, so `flutter analyze` at the root does not walk in.

## Static, not server

`jaspr: mode: static`: every route is rendered to HTML at build time. The content is known then
(the deploy workflow pulls it from the content API before building), so the output is a static
bundle for Firebase Hosting and needs no running server.
